# Nanopore Allele-Specific Methylation Workflow 

This workflow performs methylation analysis for sample `OTC3` using:
- `minimap2` for ONT alignment
- `clair` (v2.1.1) for SNP calling
- `vcftools` for VCF filtering/subsetting
- `whatshap` for SNP phasing
- `nanopolish` for per-read methylation calling
- `nanomethphase` for haplotype methylation phasing and DSS-based DMA

All tools are configured to run through Singularity images.

## Expected inputs

Edit `config/samples.tsv` and `config/config.yaml` before first run.

Required:
- FASTQ (merged ONT reads) per sample
- FAST5 directory per sample

Reference is downloaded automatically from `reference_url` into `reference_fasta` and indexed with `samtools faidx`. The default is the GENCODE release 38 primary assembly, whose contig dictionary matches the historical OTC3 VCF; do not substitute the GRCh38 no-alt analysis set when reproducing this result.

## Run

```bash
snakemake --use-singularity --cores 24
```

For cluster/HPC execution, add your profile/executor flags as usual.

Output is under `results/`.

Stdout/stderr logs are written under `logs/` (for example, `logs/OTC3/nanopolish_index.log`).

## Historical VCF filter reconstruction

To reconstruct the published chrX filter from the previous raw Clair calls:

```bash
snakemake -s workflow/reconstruct_previous_filter.smk --cores 1
```

This compares `previous_results/OTC3.chrXcalls.vcf` against the chrX records in
`previous_results/GSM9351546_OTC3.vcf.gz` and writes the ranked filter grid to
`results/OTC3/benchmarks/previous_chrx_filter/`.

## Build custom images (optional)

By default, the workflow uses the prebuilt NanoMethPhase image `docker://docker.io/szsctt/nanomethphase:latest` (see `containers.nanomethphase` in `config/config.yaml`).

If you need to build your own NanoMethPhase image, this repo includes a GitHub Actions workflow:

- `.github/workflows/build-custom-tool-images.yml`

It builds and pushes to Docker Hub:

- `nanomethphase`: local custom multi-stage Dockerfile at `docker/nanomethphase.Dockerfile`

The custom NanoMethPhase image keeps compile dependencies in a build stage and ships a smaller runtime stage with:
- `nanomethphase` + `whatshap` (Python venv)
- `samtools` / `tabix`
- R + Bioconductor `DSS` (for `dma`, pinned to `2.58.0`)

Set these GitHub repository secrets:

- `DOCKERHUB_USERNAME`
- `DOCKERHUB_PASSWORD` (Docker Hub access token or password)

Then run `.github/workflows/build-custom-tool-images.yml` via **Actions > Run workflow**.
After the first successful push, set your Docker Hub namespace in `config/config.yaml`:

- `containers.nanomethphase`

## Notes on defaults

- XIST region default is `chrX:73813879-73862026`
- The default SNP filter for phasing is the reconstructed historical filter: biallelic SNPs only and `QUAL >= 751` (`snp_filter.biallelic_snp_only`, `snp_filter.min_q`). The unfiltered Clair VCF is retained separately at `variants/OTC3.vcf.gz`.
- Clair model files are automatically downloaded/extracted to `resources/models/clair/` from `clair_model.source_url`.
- DMA defaults include `dma.dss_version: "2.58.0"` and a runtime check in `nanomethphase_dma`.
- Current reproduction defaults use minimap2 `2.18--h5bf99c6_0` with `map-ont`, Clair `2.1.1--0` with ONT model `122HD34.tar`, threshold `0.125`, minimum coverage `4`, and WhatsHap `1.0` (available in early 2021).
- If any container tag is unavailable on your system, update `containers:` in `config/config.yaml`.
- VCF metric summaries (`QUAL`, `DP`, `AF`) are generated by `workflow/scripts/summarize_vcf_metrics.py`.
